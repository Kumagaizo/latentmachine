Verify

Did the AI get every row right?

Paste the original records and what the AI gave you back. Verify infers the majority rule, applies it across the batch, and flags every row that doesn't match.

Open Verify →

Say you gave an AI 200 customer records to clean up. On most rows it did the same things: lowercased the email, split the name into two fields, turned "yes" into true. Verify reads all 200 before-and-after pairs and works out that pattern, which is the rule the AI was apparently following. Then it re-checks every row against it. Row 137 says "TRUE" instead of true? Flagged. Instead of proofreading 200 rows, you look at the 3 that broke the pattern and you can read the rule to see what the AI actually did.

Infer

Fix what the AI got wrong. Keep the rule.

Show the correct transformation with one or two examples. Latentmachine infers the deterministic rule, verifies it against your evidence, and exports it as code you own. Replace the inconsistent AI step with a rule that always holds.

Open Infer →

Say a webhook sends data in one shape and your database needs another. Instead of writing the conversion code, you paste one example of each: this is what arrives, this is what it should become. Infer compares the two and works out the exact steps that turn one into the other. Rename this field, join those two, turn that string into a number. It lists the steps so you can check them, says so when one example isn't enough to be certain, and hands you finished code that runs anywhere. You showed it what you meant and it wrote the function.

Regex

Build a regex from yes and no.

Mark strings that should match and strings that should reject. Regex returns a readable pattern verified against every example, or asks for one more when the pattern is under-proven.

Open Regex →

A regex is a search pattern that describes the shape of text "two letters, a dash, then numbers" in a notation almost nobody can write from memory. Here you skip the notation. Paste examples that should match (AB-2041, XY-100) and examples that shouldn't (AB2041, ab-99). The engine works out what separates the two piles and writes the pattern for you. Then tests it against every example you gave. If your examples leave two interpretations open, it doesn't guess; it tells you and asks for one more.

jq

Select the JSON you want. Keep the jq that finds it.

Click the values you want, or show the shape you need. jq Builder writes the expression, guaranteed to return exactly that, and explains it in plain English.

Open jq →

jq is a small language for pulling values out of JSON, the format most APIs speak. Powerful, but the syntax is its own little learning project. The builder skips it. Paste your JSON and click the values you want: the email buried three levels deep, the price inside a list. The engine writes the jq expression that returns exactly what you clicked from this file or any file shaped the same. You get the expression, a plain-English line saying what it does, and proof it returns what you picked.

Trace

Understand your data in seconds.

Paste or import structured data. Trace profiles every field, surfaces missing, unusual, or repeated values, and compares datasets by safe keys. It runs locally and without an LLM.

Open Trace →

Imagine opening a spreadsheet from someone else with thousands of rows and no explanation. Trace gives it a careful first look: what each column contains, which values are missing, what looks unusual, and whether two versions changed. It does not decide whether the data is good or bad. It shows the evidence and points you to the exact fields and records worth checking. Everything stays in your browser.
